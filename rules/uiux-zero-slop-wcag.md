# UI/UX, Design System & Zero AI-Slop Rules

## 1. Objective
Ensure front-end user interfaces deliver elite craft, accessible usability (WCAG 2.2 AA), and complete elimination of "AI Slop" — the generic, unbranded, careless artifacts generated by novice AI prompting.

---

## 2. Zero AI-Slop Ban List (Strict Visual Mandate)

Flag and penalize any occurrence of the following AI slop patterns:

### 🚫 The AI Slop Hall of Shame
1. **Generic Purple/Blue Gradients:** Arbitrary `bg-gradient-to-r from-purple-600 to-blue-500` applied to buttons, cards, or hero text without brand rationale.
2. **Unstyled Emoji Icons:** Using emojis (e.g., 🚀, 💡, 🔥, 📊, ⚡) directly inside buttons, cards, or navigation instead of professional SVG icons (such as Lucide React, Heroicons, or Radix Icons).
3. **Meaningless Tracked-Out Eyebrows:** Uppercase, tracked-out micro-labels floating above every heading (e.g., `EXPLORE THE FUTURE` with `tracking-[0.2em] text-xs`) where a simple, strong heading suffices.
4. **Arbitrary Non-Token CSS:** Using arbitrary hardcoded Tailwind values like `p-[17px]`, `w-[342px]`, `text-[#324512]`, or inline `style="..."` rather than adhering to established design tokens.
5. **Cream/Pastel + Generic Serif Slop:** Default warm cream backgrounds paired with generic serif headings attempting to fake "luxury" without typography hierarchy.
6. **Card Clutter:** Wrapping every single paragraph or metric in identical cards with thick fuzzy drop shadows (`shadow-2xl shadow-purple-500/10`).

---

## 3. Deliberate Design & Token Hygiene

Require front-end code to use a structured Design Token system:

### 3.1 Color Palette & Semantic Tokens
* **Base Theme:** Use neutral foundations (`bg-background`, `text-foreground`, `border-border`).
* **Semantic Roles:** Reserve vibrant colors strictly for functional feedback:
  * **Success:** Green/Emerald (Positive trends, completed tasks, passing tests)
  * **Warning:** Amber/Yellow (Rate limits, approaching quotas, deprecations)
  * **Destructive/Critical:** Red/Rose (Errors, security leaks, breaking changes)
  * **Info/Accent:** Indigo/Blue (Active navigation, focus rings, selected items)
* **Contrast Ratios (WCAG 2.2 AA):**
  * Normal text ($< 18\text{pt}$ / $24\text{px}$): Contrast ratio must be at least **4.5:1** against the background.
  * Large text ($\ge 18\text{pt}$ or bold $\ge 14\text{pt}$): Contrast ratio must be at least **3.0:1**.

### 3.2 Typography Scale
Ensure distinct, predictable optical hierarchy:
* **Display / H1:** Bold, tight line-height (`leading-tight`), controlled letter-spacing (`tracking-tight`).
* **Body Text:** Readable line-height (`leading-relaxed` or `1.5 - 1.6`), high contrast.
* **Code / Numbers:** Monospace font (Geist Mono, JetBrains Mono, Fira Code) with tabular figures (`font-mono tabular-nums`) so numbers align vertically in tables.

### 3.3 Touch Targets & Spacing Rhythm
* **Minimum Touch Target:** Interactive elements (buttons, links, icon toggles, inputs) must have a clickable area of at least **44×44px** on touch devices (`min-h-[44px] min-w-[44px]` or adequate padding).
* **Spacing Scale:** Stick to 4px / 8px spacing steps (`p-2`, `p-4`, `p-6`, `p-8`).

---

## 4. Comprehensive Interactive States

Flag any component or interactive element that lacks required states:

Every interactive component MUST implement:
1. **Default State:** Clean, readable resting appearance.
2. **Hover State:** Subtle luminance change or border highlight (150ms transition).
3. **Active / Pressed State:** Subtle scale or color shift confirming click.
4. **Focus-Visible State:** Clear, high-contrast focus ring (e.g., `focus-visible:ring-2 focus-visible:ring-offset-2 focus-visible:ring-primary focus-visible:outline-none`). **NEVER remove `outline: none` without a visible alternative.**
5. **Disabled State:** Reduced opacity (`opacity-50`), `cursor-not-allowed`, and `aria-disabled="true"`.
6. **Loading / Skeleton State:** Content placeholders preventing layout shifts (CLS) during data fetching.
7. **Empty State:** Helpful illustration or icon, explanatory text, and a clear call-to-action (CTA) button when lists or data tables have no items.
